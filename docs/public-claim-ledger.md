# Public claim ledger

This ledger records the boundary used for public copy. Employers and internal products remain anonymized across the site.

| Area | Available support | Public treatment |
|---|---|---|
| Recommendation-quality role and viewer-side measurement work | Owner-provided resume and background | State the measurement scope and contribution to product decisions; publish no metric formula, segment result, effect size, or launch threshold. |
| Exact viewer-efficiency definition and historical experiment protocol | Not confirmed for public use | Do not reconstruct the numerator, denominator, assignment, preregistration, or historical segment results. Put ideal protocol in an explicitly illustrative example. |
| Enterprise AI evaluation responsibilities | Owner-provided resume and background | Describe task quality, unsupported claims, tool use, and launch readiness as reported experience. Do not invent a benchmark result or adoption outcome. |
| Enterprise failure trace | No public client incident is cleared | Use only the self-authored illustrative reconstruction shown on the case page. |
| Debrief adoption | Owner confirmation of early external users | Say that early users exist beyond the author; report no user count, retention, payment, accuracy, or product-market-fit claim. |
| Narrative pipeline | Owner-provided project background; private repository and licensed sources | Describe the running private pipeline as reported work. Attribute public scores only to the checked-in self-authored fixture and deterministic baseline. |
| Employment and education periods | Owner-provided resume | Show month-and-year chronology; keep employer and internal product names anonymized. |
| Resume download | No approved PDF in this repository | Keep the About fallback. Do not generate a placeholder or a dead `/resume.pdf` link. |

When a claim gains a publishable source, update this ledger and the public copy together. A method that would be good practice is not evidence that it was used historically.
